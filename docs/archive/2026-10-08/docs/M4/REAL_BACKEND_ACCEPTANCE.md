**2026-10-06：工程验收与作者失败时序复述通过，M4.2 收尾。**
单卡 RTX4090、vLLM 0.8.5、Qwen2.5-7B-Instruct；网关与模型服务在同一远程
机器，分别仅监听 127.0.0.1:8000 和 8001。不是 benchmark 或生产负载验收。

## 实际 HTTP 验收

验收使用专用网关，顺序发送六个业务请求；完成日志数量与请求数量一致，
按顺序核对状态、原因、尝试次数和清理结果。

| 场景 | HTTP | 尝试次数 | 结果 |
| --- | --- | ---: | --- |
| 正常非流式 | 200 | 1 | 真实模型名、非空回答 |
| 正常流式 | 200 | 1 | 65 个 JSON SSE 事件、非空生成内容、[DONE] |
| 未配置的 mock-model | 503 | 0 | no_backend_available |
| 后端停止，探测状态仍健康 | 502 | 1 | backend_transport_failure，无重复尝试 |
| 探测已将 A 标为不健康 | 503 | 0 | no_backend_available |
| 模型重启且探测恢复健康 | 200 | 1 | 真实模型回答再次成功 |

健康指标实测 1 → 0 → 1，全程没有 backend-b 指标；所有请求清理正常，最终
infergate_active_requests 为 0。程序核对 backend.pid 的 vLLM 命令后才停止
本任务模型服务，随后以原启动参数恢复。立即请求的 502 是本次实际观察；
一般调度时探测可能先更新，因此脚本允许该窗口返回 502 或 503，保留实际
结果，不将时间竞争伪装为确定时序。

原始证据：[完整通过记录](evidence/gateway-2026-10-06.json)。首次执行在全部
HTTP 场景完成后，因 AI 验收脚本错误期待日志原因 no_backend 而失败；实际
日志为 no_backend_available。修正工具后重新执行通过，未修改网关核心。
保留 [首次失败记录](evidence/gateway-first-attempt-2026-10-06.json)。

## 运行与边界

网关 PID 3481，最终恢复模型父进程 PID 4256；这些是验收时快照，后续以
各自 PID 文件和实时检查为准。两项服务保留运行，复现安装、启动及验收脚本
见 [远程环境说明](REMOTE_ENVIRONMENT.md#单后端网关部署)。

单实例验证不证明双实例轮换或冗余；对应 mock 测试保留。生成使用
max_tokens=64，可能截断，不据此判断模型能力或 token/s。没有进行并发性能
实验、取消场景的真实 GPU 验收或长期稳定性验证。当前 vLLM 未声明 Responses，
M4.3 需另定兼容后端/版本，不通过 Chat 转 Responses 伪造支持。

## 作者复述与分工

作者主导配置关键路径；AI 主导环境、部署、验收工具和证据整理，共同完成
测试与 review。

作者随后独立复述：先出现 502 表示传输错误、无法连接后端，健康探测更新后
转为 503 无可用后端；恢复后由 HealthChecker 更新后端健康状态。该解释的
状态转换与责任归属正确。AI 补充：若探测先完成，请求可直接返回 503，并非
每次停机都必然先出现 502。当前单后端对应 502 一次尝试、503 零次尝试，
由实测与持久测试支持；作者本次没有单独复述次数，不将该部分记为独立回答。
