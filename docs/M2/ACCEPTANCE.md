# M2 验收记录 — 2026-09-26

## 结论

**M2 第一版在约定的单进程学习范围内通过验收。** per-key 请求速率、全局并发
名额和 fallback 次数的限制均有可复现证据；作者已完成相关核心实现与 teach-back。
这不等于整个服务的内存、总响应时间或生产过载风险都已被约束。

## 1. 当前行为

| 项目 | 实现 |
| --- | --- |
| key | `X-InferGate-Key`；缺失、空白为 400；作为配额标识，不承担认证 |
| per-key 配额 | runtime 容量 2，每秒补充 1；超额返回 429 |
| 全局并发 | runtime 上限 2，所有 key 共用；满时立即 503，队列容量 0 |
| 扣费顺序 | 验证 → per-key 扣费 → 并发获取 → 选路；后续拒绝或失败不退费 |
| 普通响应 | 完成下游读取或失败/取消后释放名额，不等待客户端读完缓冲响应 |
| Streaming | 发送与下游清理结束后释放；交接前由 endpoint，交接后由响应包装负责 |
| Fallback | 仅 ConnectError/ConnectTimeout 可触发，最多 2 次尝试，排除已尝试 ID |
| 重试资源 | 同一请求不重复扣令牌、不重新获取并发名额、不在尝试间释放 |
| 最终失败 | 首次无候选为 503；传输失败后无备用或次数耗尽为 502，标识最后尝试者 |

## 3. 本地真实 HTTP 验收

使用 [verify_m2.py](../../scripts/verify_m2.py) 在 127.0.0.1 上启动三个独立
Uvicorn 进程：gateway 8000，两个受控 mock backend 8001/8002。
网关复用正式 `create_runtime_app()`。mock 提供测试用的流保持与释放接口，
让并发占用与客户端断开可稳定观察。

测试将健康探测间隔从默认 5 s 临时改为 **3600 s**，让停止 backend 后，其健康
状态在测试期间仍保持启动探测结果，专门验证“选路仍认为健康，但连接已失败”的
fallback。正常周期性健康更新仍由自动化测试验证。本次没有修改正式默认配置。

7 组检查全部通过，原始结构化记录见 [acceptance_evidence.json](acceptance_evidence.json)：

1. 缺失 key 返回 400。
2. 同 key 连续请求得到 200、200、429；其他 key 仍为 200；等待补充后恢复 200。
3. 两条保持中的真实 HTTP 流占满容量，第三个不同 key 的请求得到并发 503。
4. 一条流正常结束后，新请求恢复 200。
5. 主动关闭另一条客户端流，下游观察到流关闭；随后两条新流可同时进入，证明
   两个名额均已恢复。此实验覆盖主动关闭，不代表所有网络故障模式。
6. 停止 A，游标指向 A 且健康状态尚未更新：请求通过 B 返回 200。
7. 再停止 B：两次连接失败后返回 502，最后 backend 为 B。

脚本在成功或失败退出时清理自己创建的进程。本次记录确认三个进程全部已停止。

复现方式（8000–8002 端口必须空闲）：

```bash
uv run pytest -q
uv run python scripts/verify_m2.py --output /tmp/infergate-m2-evidence.json
```

## 4. 作者理解与分工

- 作者主导：token bucket、并发计数、endpoint admission 与责任交接第一版、
  router 排除、异常分类及有界 retry 循环。
- AI 配套：focused review、框架响应包装、测试 fixtures、自动化与真实 HTTP
  验证、文档记录。
- 作者解释了分段补充的累积、同步更新的事件循环边界、endpoint 返回不等于流
  结束、`__call__` 包装覆盖 headers 失败，以及失败后无备用仍保留 502 的原因。
- 本轮关键经验：先确定状态含义与资源责任，再验证失败行为；参数校验不应在
  多层重复扩张，测试也不能只看最终计数而忽略重复释放。

## 5. 已知边界与后续工作

- 配额和健康状态均限于单进程；客户端自报 key 可更换，不提供可信身份隔离。
- key→bucket 字典没有数量上限或清理策略；大量不同 key 可使状态持续增长。
  因此不能声称网关整体内存有界。
- 有并发和尝试次数上限，没有总生成时限；持续输出的流可以长期占用名额。
  shielded 下游清理也没有独立 deadline，关闭卡住未被本轮测试排除。
- 未验证生产模型服务、性能/吞吐、长期负载、多进程、网络黑洞或任意重复取消。
- `release()` 的数值封顶不检测所有重复释放，正确性依赖所有权路径及对应测试。
- 既有 runtime 重复 lifespan 和占位 console command 技术债仍未阻塞本轮。

这些边界作为后续部署或范围扩展的输入，不能从本次通过推导出生产就绪。
